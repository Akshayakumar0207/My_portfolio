01 / 06 · One Tap

One Tap Voting System

A secure, browser-based voting platform that combines email OTP authentication, live camera and audio monitoring, and a blockchain-style vote ledger, so a vote can be cast in a single tap and verified afterward.

Live demo

What I built

One Tap Voting System is a web app for running tamper-evident digital elections. Voters verify their identity with an email OTP, pass a live monitoring check, and cast a vote with one click. Each vote is hashed, assigned a block number, stored as an immutable record, and returned to the voter as downloadable proof. Admins get a separate OTP-protected dashboard to control voting sessions and watch results in real time.

Core features

  • Email OTP two-factor authentication for voters, plus a separate admin-only OTP for dashboard access.
  • One-tap voting: instant vote casting with a single click.
  • Vote hashing with SHA-256-style transaction hashes and sequential block numbers.
  • Immutable vote records with a complete audit trail and a blockchain-style timeline log.
  • Camera and audio monitoring during voting, with an Auto-NOTA trigger when a security breach is detected.
  • Session-based access control: votes are accepted only inside an active voting period.
  • Admin dashboard with session management, real-time vote counting, and charts.
  • Downloadable vote proof as confirmation after casting.

Workflow

  • User registration: email OTP verification authenticates the voter.
  • Profile setup: voter information and verification status are recorded.
  • Session check: the system validates that a voting period is active.
  • Camera activation: live monitoring starts, with AI-simulated detection.
  • One-tap vote: the vote is recorded on a single click.
  • Blockchain hash: an immutable transaction hash is generated.
  • Vote storage: the encrypted vote is saved to the database.
  • Confirmation: the voter sees proof with a download option.

Architecture

01 · BrowserReact 18 SPA with Tailwind, Shadcn/UI, and Framer Motion
02 · Client logicReact Router, React Query caching, camera/audio monitoring hooks
03 · BackendBase44 BaaS: entity system, RESTful APIs, real-time queries
04 · SecurityEmail OTP, session management, role-based access (admin/user)
05 · LedgerSHA-256-style hashing, sequential block numbers, immutable records

Technical decisions

Base44's entity system provides structured storage for voters, sessions, and votes, and its real-time queries power live result updates without manual polling. React Query handles data fetching and caching, so the UI stays responsive during active sessions. Votes are never modified after creation: each record carries a hash and block number, which gives a full audit trail and a verifiable timeline. Role-based access separates voter and admin flows, and a security breach during monitoring triggers Auto-NOTA, which enforces the rules without admin intervention.

Note: the blockchain layer and the camera/audio detection are simulated (SHA-256-style hashing and AI-simulated detection), not a distributed ledger or a production ML pipeline.

02 / 06 · StudySphere

Collaborative Virtual Study Platform

A collaborative virtual study platform where students join study groups, chat in real time, attend live video classes, share materials, and get help from an AI study assistant, all in one browser-based workspace.

Live demo GitHub

What I built

StudySphere is designed as a single place for group learning. Students form or join study groups and talk through group chat. They can also start live video classes and share notes and resources. When they get stuck, they can ask a Gemini-powered AI assistant. The frontend is a React 19 + TypeScript app, and the backend is an async FastAPI service backed by a 24-table Supabase PostgreSQL schema.

Core features

  • Group chat for study groups and communities.
  • Live video classes embedded through Jitsi Meet.
  • Study material sharing, so groups can upload and access notes and resources.
  • AI study assistant powered by Google Gemini for doubts, explanations, and revision help.
  • Relational data model of 24 tables in Supabase PostgreSQL covering users, groups, messages, classes, and materials.
  • Async FastAPI backend for fast, concurrent API handling.
  • Deployed on Vercel (frontend) and Render (backend).

Architecture

01 · BrowserReact 19 + TypeScript SPA built with Vite
02 · APIFastAPI (async) REST backend on Render
03 · DataSupabase PostgreSQL with 24 normalized tables
04 · IntegrationsJitsi Meet for live classes, Google Gemini for the AI assistant
05 · DeploymentVercel (frontend) + Render (backend)

Technical decisions

TypeScript on the frontend catches data-shape errors early across a large feature set. FastAPI's async model keeps chat and AI requests from blocking each other. Supabase PostgreSQL gives a strongly relational schema for users, groups, classes, and materials. Jitsi Meet avoids building video infrastructure from scratch, so live classes work with no custom media servers. Gemini is called from the backend, which keeps the API key off the client. Splitting the deployment lets the frontend and backend scale and redeploy independently.

React 19TypeScriptViteFastAPIPython (async)SupabasePostgreSQLJitsi MeetGoogle GeminiVercelRender

03 / 06 · ParkEase

Real-Time Parking Slot Finder

A web platform that helps drivers find and book nearby parking slots while letting space owners list and manage their spaces, with availability updating live across every connected browser.

GitHub

What I built

ParkEase connects two sides of the parking problem. Drivers search for available slots near their location, see them sorted by distance, and book one. Owners list their parking spaces and manage availability. When a slot is booked or freed, every open browser sees the change instantly through Socket.IO, so nobody books a slot that is already taken.

Core features

  • Nearby slot search, with results ranked by distance using the Haversine formula.
  • Slot booking for users, with live availability.
  • Owner portal to list and manage parking spaces.
  • Real-time updates across browsers with Flask-SocketIO, with no manual refresh.
  • JWT authentication with separate user and owner flows.
  • MySQL relational storage for users, spaces, slots, and bookings.

Workflow

  • Sign up / log in: JWT-based authentication for users and owners.
  • Search: the user's location is used to find nearby parking spaces.
  • Distance ranking: the Haversine formula computes the distance to each space and sorts the results.
  • Select a slot: the user views live availability for a space.
  • Book: the booking is saved to MySQL and the slot is marked occupied.
  • Live broadcast: Socket.IO pushes the update to all connected clients.
  • Owner view: owners see bookings and slot status update in real time.

Architecture

01 · BrowserReact + Vite SPA
02 · APIFlask REST backend with JWT-protected routes
03 · Real-timeFlask-SocketIO broadcasting slot changes to all clients
04 · LogicHaversine distance calculation for location-based search
05 · DataMySQL for users, spaces, slots, and bookings

Technical decisions

Socket.IO was chosen over polling so slot status changes reach every client immediately, which prevents double bookings from stale views. The Haversine formula gives accurate great-circle distances from latitude and longitude, so results rank by real proximity without a paid maps API. JWT keeps the API stateless and lets user and owner roles share one backend. MySQL's relational model suits the clear relationships between owners, spaces, slots, and bookings.

04 / 06 · TrackIt

Real-Time College Bus Tracking Platform

A production-ready full-stack transit platform with role-based access for Students, Parents, Drivers, Bus Incharges, and Admins, featuring live GPS tracking, AI-powered route optimization, QR-based boarding validation, SOS alerts, and automated attendance syncing.

Live demo

What I built

TrackIt covers the complete campus transit journey: role-based authentication, live bus tracking on an interactive map, stop-wise ETA predictions, QR boarding passes, attendance management, delay alerts, parent notifications, feedback collection, incident reporting, and an administrative control center.

The system is designed as an end-to-end real-time transportation safety platform and highlights AI-driven delay prediction, geolocation-based boarding flows, and proactive parent communication.

Core features

  • 5-role authentication with role-specific dashboards (Student, Parent, Driver, Bus Incharge, Admin) and persistent sessions.
  • Real-time GPS tracking via the Geolocation API with live location updates on Leaflet maps for parents and admins.
  • AI-powered route optimization and delay prediction using LLM-driven analysis of route performance and traffic conditions.
  • QR-based boarding validation with driver-side scanning and stop-wise boarding checklists.
  • SOS emergency alerts with parent and admin email notifications and a dedicated SOS response center.
  • Attendance management with incharge-driven check-in, auto-attendance, history, and CSV/Google Sheets export.
  • Bus alteration workflow with automatic student and parent email alerts and temporary tracking links.
  • Parent portal with live child tracking, proximity alerts, leave calendar, and incharge chat.
  • Admin dashboard with live fleet map, KPIs, attendance/delay charts, feedback analytics, and incident tracker.

Real-time & data flow

01 · ClientReact + Tailwind CSS + Framer Motion
02 · TrackingGeolocation API + Leaflet maps
03 · BackendBase44 BaaS (entities, auth, functions)
04 · AILLM route optimization & delay prediction
05 · NotificationsEmail + in-app + push (PWA)

Technical decisions

The platform uses Base44 entities for structured persistent data across 17 schemas (Student, Parent, Driver, Bus, Ride, Attendance, Alert, SOSAlert, Incident, Feedback, RouteAnalytics, and more) and LLM integration for actionable route optimization suggestions. The architecture emphasizes real-time subscriptions for live ride updates, PWA installability for native-like mobile use, and a role-isolated UX where each user type sees only the data and actions relevant to them.

Its signature capabilities are AI-powered delay prediction, real-time parent notifications, and a comprehensive QR-based boarding system.
